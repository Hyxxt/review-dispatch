# 评价派单台

解压后双击 index.html。工具在本机浏览器运行，使用本地代码，无需安装依赖或提供模型密钥。上传文件只在当前标签页中处理，刷新前请保存需要留档的交接 CSV。

## 批量导入与交接

1. 点击下载模板，或在 Excel 中把平台导出的评价保存为 CSV。建议填平台、店铺、评价 ID、品牌、内部 SKU、商品、星级、时间、原文、批号与来源。支持 UTF-8、GB18030，正文可带逗号、引号和换行。单文件最多 8 MB、10,000 行。
2. 可以分平台追加文件。同一平台、店铺和记录 ID 的重复行跳过。跨平台商品按品牌和内部 SKU 汇总，需要先在该列填同一套商品主数据编码。缺 SKU 的条目按平台、店铺与商品名暂归组，派单和导出带「待核对」。
3. 一条评价允许产生多个不同责任项。可在详情查看原文、命中依据和来源，标记确认、撤销误判或改责任口。复核状态只用于当次选定的证据集合。每个 CSV 只含被分给该责任口的待复核及已确认工单，按 P1、P2 等优先级排序。每行对应一条工单证据，同组评价数在同组内会重复，不能直接对该列求和。
4. 上方指标按当前筛选范围统计去重的评价条数，风险分项允许一条评价命中多种线索。低星比例的分母是导入文件中有有效星级的评价；平台只导出部分评价时，结果对应这批样本。

## 风险与问答

疑似不良反应列为 P1，建议交品控核对原话、批号和使用时间线。功效、真伪、临期列为 P2 线索。规则匹配用于分流复核，不作诊断或鉴定。纯咨询和常见否定表达有基本过滤，复杂语境仍需要人工判断。普通归因可保留一条评价的其他服务问题，风险评价本身在看板单独计数。

问答是独立输入。答案数量明确为 0 才算「零回答」，空白为未知；同商品至少 2 条零回答的同主题问题优先出现。孕期/哺乳期与敏感肌分开，工具不生成适用性答复。

交接表保留输入原文，遮蔽符合规则的常见手机号和邮箱；来源链接会移除常见的凭据查询字段。工作流遵循不删差评、不刷好评、不生成骚扰买家改评的话术。

## 公开样本与验证

内置 9 条可回查的京东公开评价摘要，带原页面链接。它们是公开展示样本，无法代表当期店铺评价分布。出处包括 [氨基酸洁面公开评价](https://www.jd.com/zxnews/3f1a6483de53e461.html)、[爽肤水公开评价](https://www.jd.com/phb/zhishi/9512850011db8f2d.html) 和 [谜草集排行榜点评](https://www.jd.com/phb/key_16750101dafed13c8cecb.html)。样本中没有经核实的风险投诉或「问大家」数据。回归测试中的风险和问答是明确标记的测试输入。

CSV 解析与序列化复用 [Papa Parse 5.7.0](https://github.com/mholt/PapaParse/releases/tag/5.7.0)，许可在 vendor/PapaParse-LICENSE.txt。运行 node test.cjs 可复测规则。


## 取样与覆盖验收

目标入口是 https://item.jd.com/11131685286.html 的「商品评价」区。当前环境被京东频控页挡住，没有从该入口取得评价。内置聚合页记录继续用于演示，JD1 保留若干可逐字回查的原文片段，以及零元拼购、团长身份、第三方卖家与愿给五星的上下文。

在能正常访问商品页或拿到店铺授权导出的情况下，先记录一组最近评价，再补一组一至二星评价，以 30–50 条去重样本为目标。两组分别用「最近未筛」和「一至二星」标记。优先留平台评价 ID；拿不到 ID 时留商品来源链接与评价日期。若某类不足两条，在结果中保留缺口。

评价模板包含采样来源、采样分组、购得方式、店铺经营类型、人工归因、人工风险。购得方式用实际信息填「正常购买」「零元拼购」「赠品」或留空；自营和 POP 属于店铺类型。平台标签和买家自述也可以在字段里注明依据。两项用于分层复核，不改变文本归因。

来源使用「商品评价区」「授权后台导出」「公开聚合页」「来源待核」或「测试样本」。人工标签请先独立阅读原文填写，多个标签用顿号隔开，确认无问题时填「无」，未标注时留空。覆盖表仅统计被标为商品评价区或授权后台导出、同时有可追溯证据的记录。命中以人工标签为参照，多报仅对已填人工标签的行计算。每类条数用于判断覆盖程度，不是准确率证明。

导入原文按原字符串保留在当前标签页。检测到手机号或邮箱时，默认交接导出遮蔽；需要查证时可以在本机证据弹窗展开原文。下载采样模板、查看证据与导出 CSV 均为本地操作。
导入后可使用「备份本机原文」为当前筛选另存 JSON，完整保留源字符串；原文档案可能含个人信息，请按公司档案流程保管。
